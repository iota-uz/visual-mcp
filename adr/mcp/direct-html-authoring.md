## Контекст

В сессии Workbench агент сначала записал генерируемый HTML на локальный диск,
запросил upload URL, загрузил его через curl и лишь затем вызвал canvas_save.
Сопровождающий явно определил цель: рисовать HTML только через MCP с минимальными
накладными токенами; локальная файловая система нужна для медиа и существующих файлов.

## Решение

canvas_save принимает html для одного экрана и screens для набора экранов.
Общий html с разными route передаётся один раз. Сервер создаёт стабильные
виртуальные пути, iframe-ноды и раскладку, затем сохраняет их существующей
атомарной транзакцией. Краткая форма создаёт kind=canvas, не сочетается с doc,
заменяет все страницы и prototype. Изменения отдельных фрагментов выполняются
через canvas_edit с хешами. Произвольная геометрия остаётся в doc + files[].text.

Инструкции рекомендуют прямой MCP authoring; upload URLs предназначены для
медиа и существующих файлов. Нового инструмента и клиентского upload-helper нет.

## Обоснование

Запись того же HTML в локальный Write уже расходует токены на его генерацию.
Прямая передача убирает промежуточные вызовы, а общая оболочка и инкрементальные
правки уменьшают повторение исходника. Хранение и относительные ссылки продолжают
использовать единую виртуальную файловую модель.

## Отклонённые альтернативы

- Локальный helper: сохраняет зависимость от файловой системы при генерации HTML.
- HTML внутри каждой ноды: дублирует общую оболочку и усложняет адресацию правок.
- Отдельный инструмент: существующий canvas_save уже владеет атомарной записью.

## Последствия

html/screens — полная замена композиции, а не patch; это явно указано в схеме.
Неиспользуемые исходники остаются по обычным правилам canvas_save. IDs и пути
детерминированы; конфликты, дубликаты и ограничения проверяются до первой записи.
Генерируемый HTML не возвращается в ответе. Большие дизайны разбиваются на экраны.

## Как проверить

MCP tests: одиночный экран, общий HTML с hash-маршрутами, ограничения и коллизии,
атомарная передача doc и файлов через реальный AgentGateway. На локальном стеке:
save → get → file_get → edit с хешем → checkpoint, без локальных HTML-файлов.
